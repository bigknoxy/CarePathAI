# PR Title

Initialize MVP: Core RAG ingestion, orchestration, and API scaffolding (v0.1.0-mvp)

---

## Summary

This PR introduces the initial MVP for CarePathAI. It adds the core Retriever-Augmented Generation (RAG) ingestion pipeline, multi-step orchestration scaffolding, basic REST API endpoints, initial data schema, and CI helpers required to build and produce the first release artifact. This change bundles the minimal, reviewed functionality required for internal QA and early adopter testing under the release tag `v0.1.0-mvp`.

Release artifact path: ./releases/carepathai-v0.1.0-mvp.tar.gz
Release tag: v0.1.0-mvp

---

## What changed (high level)

- New: RAG ingestion pipeline (documents -> embeddings -> vector store)
- New: Orchestration layer for multi-step care guidance generation
- New: Minimal REST API to submit patient-style records and request guidance
- New: Data schemas and example fixtures for ingestion and testing
- New: CI job templates and scripts to build the release artifact
- Chore: Project layout and README scaffolding for future docs

Files of interest (non-exhaustive):
- src/ingest/** — ingestion and embedding adapters
- src/orchestrator/** — multi-step orchestration core
- src/api/** — Express/FastAPI (whichever stack) REST endpoints and schemas
- ci/build-release.sh — builds releases/releases/carepathai-v0.1.0-mvp.tar.gz
- releases/carepathai-v0.1.0-mvp.tar.gz (generated by CI/build script)

---

## Why

We need a minimal, testable product to validate architecture decisions (RAG approach + orchestration), gather early feedback, and exercise CI/CD and release processes. Packaging this as `v0.1.0-mvp` helps communicate that this is an MVP and helps gating user testing and feedback collection.

---

## How to review (recommended workflow)

1. Read the high-level architecture notes in docs/ARCHITECTURE.md (if present) to understand the orchestration pattern.
2. Verify ingestion adapters follow secure handling of PHI-like data (no logging of raw inputs in plain text). See src/ingest/README.md.
3. Validate API endpoints in src/api against the OpenAPI schema (if present) and the example fixtures in tests/fixtures/.
4. Check CI scripts for reproducible builds and that the release artifact path is produced correctly: ./releases/carepathai-v0.1.0-mvp.tar.gz
5. Run the smoke tests described below.

---

## How to run locally (smoke test)

1. Install deps and build:

   npm ci
   npm run build

2. Start service (example):

   NODE_ENV=development npm start

3. In a separate terminal, submit an example fixture (adjust for API specifics):

   curl -X POST http://localhost:3000/api/v1/generate \
     -H "Content-Type: application/json" \
     -d @tests/fixtures/example_patient_record.json

4. Expect a 200 response with a guidance summary and routing recommendation.
